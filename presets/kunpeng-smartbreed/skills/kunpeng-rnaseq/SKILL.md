# 鲲鹏 RNA-seq 分析

把“帮我做 RNA-seq”转换成可审查的分析项目。先检查输入，再生成配置和执行计划；只有真实命令成功且产物通过门禁，才报告结果。

## 执行顺序

1. 读取 `references/input-contract.md`，判断用户处于原始 reads、已比对 BAM、raw counts 三种入口中的哪一种。
2. 收集项目目录、物种、参考基因组 FASTA、GTF/GFF3 版本、样本表、分组/批次、比较设计和计算环境。
3. 对原始 reads 入口运行：

   `python scripts/preflight.py --samplesheet <samples.csv> --reference <genome.fa> --annotation <genes.gtf> --report <project>/00_preflight/report.json`

4. 若预检失败，列出准确字段、样本或路径，不进入计算。警告项需由用户确认是否接受。
5. 按 `references/workflow.md` 创建项目配置、固定软件版本并逐阶段执行。正式运行前展示预计步骤、资源与输出目录，取得确认。
6. 每阶段保存命令、标准输出、标准错误、软件版本、校验和及产物清单。失败即停在失败阶段，不跳过、不补造结果。
7. 按 `references/output-contract.md` 验收。差异表达必须使用原始整数 counts；TPM、TMM、VST 只用于相应的展示或探索，不能混作 DESeq2 输入。

## 必须阻断的情况

- 样本 ID 重复、样本表缺少必填列、FASTQ/参考/注释不存在或空文件。
- 分组和设计矩阵不明确，样本顺序不能与元数据一一对应。
- 参考基因组与注释版本不一致，或无法说明基因 ID 类型。
- 要求直接套用内部硬编码路径、未经审核的脚本或不明来源阈值。
- 只有图或摘要、没有底层结果文件和日志，却要求宣称分析完成。

## 数据解释边界

- 把观察到的统计结果、功能注释解释和生物学推断分开写。
- 富集分析报告背景基因集、ID 映射成功率和多重检验方法。
- 不把相关性表述为因果，不凭 DEG 数量评价实验好坏。
- 用户提供的李寅 RNA-seq 原稿仅作为内部流程依据；不得把其中原创代码、内部服务器路径或账号信息原样发布。
